# WAM 能力边界假设：Smoke Test 实验规划

## 1. 研究目标

初步验证以下观点是否成立：

> WM 的作用可能主要是让 action expert 更容易学到、并更稳定地产生原本已经存在的好动作；它不一定真正扩展模型能够解决的任务或动作范围。

因此需要同时观察两件事：

1. WM 是否提高单次或少量采样下的成功率；
2. 当采样次数增加时，加入 WM 的模型是否仍然能解决更多任务，还是只是更快采样到已有的好动作。

主要指标使用 `success@k`（机器人任务中的 pass@k）：对同一个任务重复采样 `k` 次，只要其中一次成功，就算该任务在 `k` 次采样下成功。

建议首先测试：

```text
k = 1, 2, 4, 8, 16, 32
```

---

## 2. Smoke Test 1：WM 是否主要提高动作采样效率

Smoke Test 1 有两个可选方案。

### 方案一：直接比较 OpenWAM 的五个不同 WM backbone

使用 OpenWAM 在 RoboTwin 上已经公开的五个不同 backbone checkpoint，直接进行推理和 `success@k` 测试。

可比较的 backbone 包括：

- `Wan2.1-VACE-1.3B`
- `Cosmos-Predict2.5-2B`
- `Cosmos3-Edge-4B`
- `Wan2.2-TI2V-5B`
- `Wan2.1-I2V-14B`

在同一组 RoboTwin 任务上，对每个模型测试：

```text
success@1, success@2, success@4, success@8, success@16, success@32
```

重点观察：

- 不同 WM 大小是否主要在小 `k` 时体现优势；
- `k` 增大后，不同模型的差距是否缩小；
- 大 WM 是否解决了更多任务，还是仅仅更容易采样到成功动作。

#### 优点

- 几乎不需要重新训练，启动速度最快；
- 可以直接利用 OpenWAM 已经公开的 RoboTwin checkpoint；
- 适合快速判断 `success@k` 曲线是否存在有意义的趋势。

#### 潜在问题

这个比较存在不完全公允的问题。不同 checkpoint 可能同时改变了：

- WM 的参数规模；
- video backbone 的架构和类型；
- 预训练权重；
- VAE 或视觉 latent；
- 训练过程和模型状态。

因此，即使不同模型性能不同，也不能完全确定差异来自 WM 大小本身，更不能单独证明“WM 只是让动作分布变尖”。

这个方案更适合作为**快速的现象观察**，而不是最终的因果结论。

---

### 方案二：使用 FastWAM，比较是否使用 WM

重新训练三种状态，尽量保持 action expert、数据、训练设置和计算预算一致：

```text
A: action-only policy

B: WM + action expert
   训练和推理都使用 WM

C: WM + action expert
   训练时使用 WM，但推理时关闭 WM
```

然后在同一组 RoboTwin 任务上测试三种模型的：

```text
success@1, success@2, success@4, success@8, success@16, success@32
```

重点观察：

- B 是否比 A 在小 `k` 下更好；
- C 是否仍然比 A 更好；
- B 和 C 的差距是否明显；
- `k` 增大后，A 是否逐渐追上 B/C。

结果可以这样理解：

- **B 优于 A，且大 `k` 时差距缩小**：支持 WM 主要提高成功动作的采样效率；
- **C 仍然优于 A**：说明 WM 可能主要通过训练过程改变 action expert，而不是只依赖推理时的未来想象；
- **只有 B 优于 A**：说明推理阶段的 WM 使用也可能是重要收益来源；
- **B 在大 `k` 下仍明显优于 A**：WM 可能不仅提高动作概率，也可能扩展了可解决任务或动作模式。

#### 优点

- 对照关系更清楚；
- 三个模型可以使用相同的 action expert 和 RoboTwin 数据；
- 更接近验证 WM 是否具有因果作用；
- 能区分训练阶段收益和推理阶段收益。

#### 潜在问题

- 需要重新训练三种模型，实验成本明显更高；
- FastWAM 的训练、显存和调参要求可能较高；
- 如果三种模型的训练没有严格对齐，仍可能混入训练预算或优化差异。

这个方案更适合作为**可信度更高的 smoke test**，但不适合作为最先启动的低成本实验。

---

### Smoke Test 1 的选择建议

建议采用分阶段策略：

1. **先做方案一**：快速获得不同 WM 的 `success@k` 曲线，判断现象是否值得继续；
2. 如果方案一出现有意义的趋势，再做**方案二**：用更公允的 FastWAM 对照确认 WM 的作用。

如果资源和时间只允许选择一个方案，方案二的结论更可靠；如果目标是尽快判断想法是否值得投入，方案一更合适。

## 3. Smoke Test 2：π0.5 + WM 在 RoboTwin 上训练

在 π0.5 action policy 的基础上加入一个 WM，使用 RoboTwin 数据进行训练，然后和不加入 WM 的 π0.5 policy 比较性能。

最基本的对照为：

```text
A: π0.5 action-only
B: π0.5 + WM
```

两者尽量使用相同的：

- RoboTwin 任务和训练数据；
- action expert；
- 训练步数和训练预算；
- 测试任务和初始状态。

对两种模型测试：

```text
success@1, success@2, success@4, success@8, success@16, success@32
```

重点观察：

- 加入 WM 是否提高 `success@1` 和小 `k` 的成功率；
- 随着 `k` 增大，π0.5 action-only 是否逐渐追上；
- 两种模型能解决的任务集合是否基本相同；
- WM 的主要收益是否表现为更稳定、更容易采样到成功动作。

Smoke Test 2 暂时只确定总体比较方式。具体任务选取、WM 形式、训练配置和评测流程，需要先根据 RoboTwin 的任务覆盖和实际训练成本进一步确定，再单独制定详细实验规划。

---

## 4. 两个 Smoke Test 的关系

两个实验回答的问题不同：

| 实验 | 主要问题 | 结论强度 |
|---|---|---|
| Smoke Test 1 方案一 | 不同 WM/backbone 的 `success@k` 是否呈现相关趋势 | 快速，但因果性弱 |
| Smoke Test 1 方案二 | 在更严格对照下，WM 是否改变动作策略的采样效率 | 成本高，但因果性较强 |
| Smoke Test 2 | WM 是否能帮助 π0.5 在 RoboTwin 上训练出更好的策略 | 验证跨模型、跨训练设置的可迁移性 |

理想的初步结果是：

```text
加入 WM 后，success@1 和低 k 成功率提高；
但随着 k 增大，action-only policy 的差距缩小；
能解决的任务集合没有明显扩展。
```

这种结果会支持“WM 主要进行动作分布重加权或变尖”的假设。

如果加入 WM 后在大 `k` 下仍然持续解决更多任务，则说明 WM 可能具有更强的能力扩展作用，需要在后续正式实验中进一步分析。

---

## 5. 后续正式实验

Smoke test 通过后，再开展不同 WM 大小的系统实验，比较：

- 不同 WM backbone；
- 不同参数规模；
- 不同视觉 encoder/VAE；
- 不同训练数据规模；
- 不同任务难度。

这部分属于正式 scaling 实验，不放入当前 smoke test 的判断范围。
